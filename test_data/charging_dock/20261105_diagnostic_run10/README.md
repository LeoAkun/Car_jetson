# 取消末段时限后的独立自动对接实车测试

2026-11-05，用户确认车辆回到 P0 后授权一次实车测试。根代理是唯一硬件控制者，分析代理只读监控。先记录、启动硬件和静态检查，再调用一次 start。`dry_run=false`、`calibrated=true`、`auto_start=false`；共享总时限、独立客户端总时限、末段时限均为 0。末段请求速度仍为 0.025 m/s，行程、偏差与碰撞保护保持。本轮没有重试或修改生产参数。

## 结果

**用户现场确认已开始充电；程序终态仍为 `FAILED swept_footprint_obstacle`。** 测试结束后，用户针对现场状态明确回复“已亮起充电指示灯”。据此记录本轮实车已完成可充电对接，证据来自用户现场确认；本轮软件没有使用电池反馈，尚未自动识别成功状态。该确认不改变原始程序状态、停车原因或记录，也不能确定充电开始的具体时刻。

初始雷达距充电面 2.504 m；在实际距离约 0.918 m 处成功锁定，剩余目标距离约 0.458 m。末段持续 69.024 s，确实超过原 35 s 时限；轮速里程计累计净倒退 0.42506 m 后触发扫掠车身障碍停车。按停稳扫描平均桩位与轮速里程计重建，停车请求时距面约 0.493 m、还差约 0.033 m 到几何目标。这些是软件估计，不能代替实际距离测量；现场能够充电与软件仍未到达几何成功条件之间存在差异，后续需核对机械目标、轮速积分及成功判定，不能直接将该估计差值作为固定标定补偿。

## 末段运动与停车因果

末段的倒车命令持续有效，典型 `/cmd_vel_selected` 为 −0.025 m/s，ECU 为 R、motor 原始值 0.09、brake=false。前 20 s 净倒退约 0.0116 m，30–40 s 倒退约 0.2242 m；最后 19.024 s 仅净倒退约 0.60 mm，93.2% 时间双轮平均速度恰为零。记录能说明后期基本不再移动，尚不足以确定是接触、底盘低速响应还是其它机械原因。

完整桩体最后有效观测之后，控制器仍依靠锁定桩位与里程计继续运行约 33.55 s，失去完整面没有直接终止末段。停车原因为扫掠碰撞检查；邻近抽样扫描分析见 `collision_analysis.json`。精确触发帧缺失，不能断言障碍物身份。

明显的正轮速发生在停车命令之后：双轮平均正速超过 0.005 m/s 从 t302.816 开始，峰值约 +0.04382 m/s，此时 ECU 已在 N 档制动。停车请求至 FAILED 的里程计净前移约 14.04 mm，因此不能将该明显正速倒置为触发停车的原因；是否为实际回弹仍需现场确认。所有选中速度命令均未请求正向行驶。首次紧停 true 比 FAILED 晚约 1 ms，是客户端失败收尾，不是先触发的原因。

本轮还记录到 55 条“N 档、主车速字段 raw=0.2、双轮倒退”的反馈，位于 t132.84–133.43 附近，里程计持续有效，未出现新的方向未知故障。因此本轮实际复现并通过了 run08 对应反馈条件；末段主车速字段均为零。

## 结束确认与数据限制

根代理独立接收 3 s 新鲜反馈：301 条车辆状态、150 条 ECU 消息全部确认轮速和主速为零、N 档、motor=0、brake=true。硬件、控制器与记录器均已关闭，ROS 节点列表为空。

**bag 未覆盖完整测试。** bag 记录器提前因 `SQLite error (5): database is locked` 退出。分析代理曾对活动数据库使用普通只读查询；只读事务也可能持有读锁，这是并发记录干扰的可能原因，不能仅凭报错确定唯一原因。后续实时分析应使用 trace，避免直接打开正在写入的数据库。

根代理确认数据库 `quick_check=ok`，并通过 reindex 恢复已写消息的 metadata，共 119594 条消息、6144 帧雷达，ROS 时间覆盖 1793869401.069–1793869611.640，结束于锁定之前。reindex 不会恢复未记录的消息。`motion_trace.jsonl`、`monitor.log`、`motion_summary.json` 完整保留至终态，但 trace 雷达按约 0.19 s 抽样；末段缺少完整频率扫描和隐藏 Action feedback。几何误差均已标为采样重建估计，不当作精确终态反馈。
