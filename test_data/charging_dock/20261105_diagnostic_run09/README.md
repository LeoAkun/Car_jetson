# 持续轮速反馈修复后的独立自动对接实车测试

2026-11-05，用户确认车辆已停在指定 P0 后授权启动一次独立测试。根代理是唯一硬件控制方；分析代理只读记录。使用 `dry_run:=false calibrated:=true auto_start:=false`，先启动 bag 和记录器，再启动硬件，静态检查全部通过后仅调用一次 start 服务。记录器使用 `--manual-start --duration inf`；共享 `timeout=0`、独立 `action_timeout=0`，没有 90 秒总期限。本轮未调参、未自动重试。

## 结果与原因

**未完成对接；已成功按实际停车距离锁定桩位，随后因 `locked_final_timeout` 正常制动停车。** 初始充电面距离为 2.510 m，实际锁距为 0.924 m，剩余倒车距离按实测值计算为 0.464 m。锁定后的 35.019 秒内，轮速里程计只累计净倒退约 0.198 m，剩余约 0.266 m，触发仍保留的 35 秒末段局部时限。

本轮末段持续收到倒车命令，`/cmd_vel_dock` 与 `/cmd_vel_selected` 典型速度均为 −0.025 m/s，ECU `motor` 典型原始值为 0.09，R 档且 `brake=false`。实际有符号双轮平均速度的中位数仅约 −0.001905 m/s，64.3% 的时间绝对值不超过 0.0025 m/s；前 20 秒仅倒退约 0.0207 m，最后 5 秒才达到约 0.0214 m/s 的平均倒退速度。说明末段的实际低速响应明显落后于命令，35 秒预算因此耗尽；记录尚不足以区分底盘低速调节、制动释放或其它机械因素的贡献，不应直接归因为单一硬件故障。

不是 90 秒总时限触发：从动作发送到独立客户端失败约 141.7 秒。本轮也没有再次发生里程计方向未知故障，紧停不是最先触发失败的原因。

## 动态锁距与末段运动

日志明确记录 `Actual stopped dock distance=0.924 m, remaining reverse distance=0.464 m (nominal stop trigger=1.000 m)`。隐藏 Action feedback 给出锁时剩余纵向误差 0.463653 m、横向误差 +0.002945 m、航向误差 −0.4874°，满足 5 mm / 0.5° 锁定门限。根据反馈位姿与当前 0.46 m 最终几何目标反算的锁距为 0.923595 m，与日志一致。横向/航向误差是控制目标误差，不等同于原始观测的 `dock_y`。

## 轮速反馈修复验证范围

动作期间记录到 499 条 N 档且至少一侧轮速绝对值超过 0.01 m/s 的样本，反馈里程计保持更新；动作启动至 FAILED 共有 7085 条本地里程计消息，最大接收间隔约 24.0 ms，没有新的积分器故障，停车确认成功。因此本轮验证了 N 档滑行连续积分、等待实际停车、按停车后的稳定雷达位姿动态锁距及进入里程计末段。

**本轮全部主车速字段均为 0。** 没有实车复现 run08 的“N 档、主车速字段非零且双轮倒退”条件，不能声称本轮单独完成了该条件的实车复验；该特定条件的修复证据仍是 run08 原始数据回放与软件回归。本轮也未以电池反馈验收“已开始充电”。

bag 中首次 `emergency_stop=true` 的 ROS 时间为 1793867684.0905027，晚于控制器 FAILED（1793867684.0895145）约 1 ms；它是独立客户端接收到失败后执行的紧停收尾，而非导致 35 秒超时的起因。最初请求制动已在 STOPPING 阶段发出。
