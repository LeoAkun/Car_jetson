默认 `dry_run:=true`，启动后自动等待新鲜 CAN、IMU、本地里程计、扫描和 TF，确认持续停车后，把当前本地位姿保存为本次 P0，调用对接 Action。`READY` 表示预检通过，不会倒车。启动过程超时会显示具体等待项并锁定停止。默认启动会占用硬件并发出零速/刹车命令，静态预检也需准备好车辆。

```bash
ros2 topic echo /standalone_docking/state
ros2 topic echo /charging_dock/state
ros2 topic echo /charging_dock/observation
ros2 topic echo /docking_feedback_odometry/state
```

`observation.pose` 已转换到突出充电面，`visible_width` 描述实际背板。无需手动填写地图坐标或发送 Action。

## 实际倒车测试

先完成机械外参、25 cm 背板回波、约 5.7 cm 偏移、实车轮廓、IMU 轴向、CAN 速度单位与制动标定。共享配置中的轮廓和转向参数仍是待实测值。确认后可在启动时显式启用运动：

```bash
ros2 launch charging_dock_standalone standalone_docking.launch.py dry_run:=false calibrated:=true
```

此命令会在传感器就绪且实测停车后**自动开始倒车**。若希望启动传感器后再手动开始，加 `auto_start:=false`：

```bash
ros2 launch charging_dock_standalone standalone_docking.launch.py dry_run:=false calibrated:=true auto_start:=false
ros2 service call /standalone_docking/start std_srvs/srv/Trigger '{}'
```

启动参数只覆盖本次运行，不改变共享配置的默认运动关闭状态。使用 `dock_params:=/绝对路径/relative_docking.yaml` 指定测试配置，`hardware_params:=/绝对路径/hardware.yaml` 指定硬件配置。首次短程测试可复制共享配置并设置 `run_limit: 0.10`；达到行程上限会停止并返回失败，不会当作已对接。

软件停止接口如下，现场保留底盘物理急停：

```bash
ros2 service call /standalone_docking/stop std_srvs/srv/Trigger '{}'
```

每次启动只执行一次对接。成功后状态为 `DOCKED`，继续保持零速，不自动驶离；本阶段不依靠电池反馈判断开始充电。失败或停止后不自动重试。要重新测试，结束本次启动、人工安全脱离并移回 P0、停车，再重新启动。不要在对接中重启本地里程计。

## 本地运动估计与限制

本包发布 `dock_odom → base_link`。当前配置启用 `zero_speed_wheel_fallback`，始终使用左右前轮反馈的平均速度（有符号 m/s）；该参数保留历史名称以兼容已有启动配置，含义已从主车速报零时回退改为持续选择轮速来源。主车速非零或切 N 档制动时也继续积分实际滑行，不将空挡直接视为静止。未启用时，沿用 `cur_speed` 按原有 km/h 约定和档位计算有符号速度，空挡非零主速缺少方向时仍失败。当前主机配置从 `0x168` 独立获取前轮反馈，不混用电机诊断报文，并限制轮速新鲜度。航向由 `/imu` 的 z 轴角速度积分。它不用发送的速度指令伪造里程计，也不发布固定不动的 `odom → base_link`。定位原点任意，P0 在停车后捕获，充电桩先验位于其后方 2.5 m。

`cur_speed` 的真实单位仍需标定：消息定义注释为 km/h，底盘 CAN 解码头文件、实现及 README 注释为 m/s。现有代码的除以 3.6 是继承的约定，尚未获得非零主车速与实测位移的交叉确认，不能视为已验证。当前本地里程计使用有符号轮速作为平移来源；主车速仍参与有效性、限速及共享控制器的保守运动检查，本次不修改其换算约定。

CAN、IMU 或启用的前轮反馈过期后停止发布新位姿并锁定停止；不会用当前时间包装陈旧数据。无效轮速、单轮绝对速度超过 0.5 m/s、运动时档位无效或 D 挡下明显反向轮速仍会停止；左右轮速差值不再单独触发停止；R 挡下实测前移允许继续并如实积分。反馈间断、倒序或时钟回退后需从人工 P0 重启。该短程积分不能替代整车定位，低速 CAN 量化、轮胎滑移与 IMU 零偏仍需实测；锁定前依据实时雷达相对位姿纠偏，锁定后依据固定桩位和实时里程计。IMU 驱动已按 ROS 轴变换，配置中的 `imu_yaw_rate_sign` 仅允许 ±1，应以实测左转/右转核对。

独立模式的平移里程计仍来自底盘 CAN：有符号轮速能处理主车速字段报零或空挡制动时失去方向的问题，但不能独立发现所有车速及轮速同时误报零的故障，也不能替代外部定位对停车状态的独立校验。实际轮径、低速反馈、制动与停车仍需现场确认。

如硬件驱动已经单独运行，可以设置 `start_chassis:=false start_imu:=false start_rear_lidar:=false`；若也已有同一雷达静态 TF，加 `publish_rear_tf:=false`。仍需确保没有其他定位节点发布 `base_link` 的父变换。独立 Mux 不接普通 `/cmd_vel`；测试客户端检测到多个 `/ecu` 发布者会停止测试，但不能阻止其他进程直接控制底盘，应先关闭重复控制链。

运动中若目标观测暂时无效或质量不足，控制器立即输出零速并保持当前控制权，等待后雷达重新连续识别稳定；实测车速和角速度都低于停车门限并持续 0.5 秒后才恢复闭环。默认最多等待 `observation_reacquire_timeout: 2.00` 秒，超时即失败停车，不使用陈旧目标位姿继续倒车。保持期间继续检查局部里程、里程突跳及行程上限。该时间是软件保护上限，尚未完成实车验证；单次测试只运行一次，故失败后仍需人工移回 P0 再启动。

后雷达只覆盖其扫描高度；低于扫描线的线缆、底座等不能仅靠它检测。结束全部启动进程后，现场停车保障仍依赖底盘自身失联制动与物理急停。
