4. 安装 Livox SDK2，依次编译工作区。

   新机不能只装 ROS 包：当前 Livox 驱动还依赖 SDK2 的库和头文件。可以直接用迁移来的 SDK 源码重新安装：

   ```bash
   SDK_SOURCE=/home/akun/workspace/Car_jetson/real_ws/src/driver/lidar/Livox-SDK2
   SDK_BUILD=/home/akun/car_migration_20261012/livox_sdk_build

   cmake -S "$SDK_SOURCE" -B "$SDK_BUILD" \
     -DCMAKE_BUILD_TYPE=Release
   cmake --build "$SDK_BUILD" -j2
   sudo cmake --install "$SDK_BUILD"
   sudo ldconfig
   ```

   随后在新机终端中执行。只有 `rosdep` 尚未初始化时，才运行一次 `sudo rosdep init`。

   ```bash
   source /opt/ros/humble/setup.bash
   source /home/akun/.local/realsense_ros/setup.bash
   rosdep update

   cd /home/akun/workspace/Car_jetson
   rosdep install --from-paths \
     real_ws/src slam/src utils/src nav2/src \
   ```

   `rosdep` 之外仍需检查 Python 依赖、Livox SDK 和底盘厂家库，因为项目的依赖声明并不覆盖全部本机配置。

   ```bash
   set -e
   CAR_ROOT=/home/akun/workspace/Car_jetson

   cd "$CAR_ROOT/real_ws"
   colcon build --symlink-install --executor sequential \
     --packages-select serial livox_ros_driver2
   source install/setup.bash

     --cmake-args -DCMAKE_BUILD_TYPE=Release
   source install/setup.bash

     cd "$CAR_ROOT/$ws"
     colcon build --symlink-install --executor sequential \
       --cmake-args -DCMAKE_BUILD_TYPE=Release
     source install/setup.bash
   done
   ```

   实际包名是 `livox_ros_driver2`，原 README 中的 `livox_ros2_driver` 名称有误。Nav2 也要编译本地修改过的源码。

5. 恢复网络、设备规则及自启服务。

   先把系统备份解压到参考目录，检查后选择性安装，避免把旧机网卡配置直接覆盖到新机：

   ```bash
   mkdir -p /home/akun/car_migration_20261012/system-reference
   tar -xpf /home/akun/car_migration_20261012/system-config.tar \
     -C /home/akun/car_migration_20261012/system-reference

   sudo usermod -aG dialout,video akun
   ```

   新机必须逐项核对以下配置：

   | 配置 | 当前值或注意事项 |
   |---|---|
   | 主机传感器网络 | `192.168.1.140/24`；新旧机同时在线时要避免同 IP |
   | Livox MID360 | 雷达 IP `192.168.1.187`，配置中的接收主机 IP 为 `.140` |
   | 前后单线雷达 | `192.168.1.12`、`192.168.1.13` |
   | CAN 网络盒 | `192.168.1.10`，远端端口 `4001/4002`，本机端口 `8002` |
   | 网卡名称 | 当前在线有线网卡为 `enp1s0`，底盘配置仍写着 `enp3s0`；新机要按实际网卡核对 |

   | 后摄像头 | `/dev/rear_camera` 依赖 udev 规则 |
   | RealSense | 当前绑定序列号 `117322074703`；更换相机需更新 |

   保留同一套传感器及安装位置时，沿用相机内参、TF 外参、IMU/LiDAR 外参和车辆控制参数。更换或移动传感器后，需要重新标定。

   检查完规则和路径后，再安装 `robot-service.service`、IMU 重置服务及脚本，执行 `systemctl daemon-reload`、udev 规则重载，并启用服务。串口用户组变更需要重新登录才生效。

   至少完成这些检查：

   - **文件完整**：归档校验通过，地图五件套、CSV、模型和每个 bag 的分片齐全。
   - **依赖与编译**：工作区编译成功，Python 导入正常，动态库没有 `not found`；处理完项目相关的 `pip check` 冲突。
   - **录包读取**：用 `ros2 bag info` 检查历史录包；回放测试先使用独立 ROS 域并隔离底盘执行器。
   - **实车传感器**：点云、IMU、GNSS、前后单线雷达及相机持续有数据，时间戳正常。
   - **定位与 TF**：重定位成功，`map → odom → base_link` 正确，RViz 中车辆位置与现场一致。
   - **导航与切图**：地图加载、航点执行、跨地图切换和失败恢复正常。
   - **底盘与外围设备**：低速验证速度转换、停止、门锁和报警功能。
   - **冷启动与持续运行**：重启后传感器服务正常，连续跑车期间没有掉设备、节点退出或资源异常。

建议新机至少预留 **100 GB 空闲空间**，内存优先按当前 32 GB 配置考虑。红绿灯识别还涉及独立的 `.150/.160` Jetson 板：仓库中的 TensorRT `.engine` 应保存，但更换 GPU、JetPack 或 TensorRT 版本后可能需要重新导出；迁移导航主机并不会同时迁移那些板上的环境。

## 一、安装新机时先创建临时管理员

第一次启动新机时，先创建一个临时管理员，例如：

```text
用户名：migration_admin
```

先不要把系统安装时的第一个用户命名为 `akun`，因为第一个用户通常会占用 UID `1000`。登录 `migration_admin` 后再创建正式用户。

## 二、检查 UID/GID 是否空闲

在新机终端执行：

```bash
getent passwd akun
getent passwd 1001
getent group akun
getent group 1001
```

正常情况下都不应输出内容。

如果其中有结果，说明用户名或编号被占用，先不要继续创建，也不要删除已有用户，需要根据实际输出调整。

## 三、创建与旧机一致的用户

使用临时管理员执行：

```bash
sudo groupadd --gid 1001 akun
sudo useradd \
  --uid 1001 \
  --gid 1001 \
  --create-home \
  --shell /bin/bash \
  --comment "akun" \
  akun
```

为新用户设置密码：

```bash
sudo passwd akun
```

这里可以设置新密码，不要求与旧机密码相同。

加入旧机原有的附加组：

```bash
sudo usermod -aG sudo,dialout akun
```

如果新机还没有 `dialout` 组，先检查系统及驱动安装是否完整，不要自行创建错误编号的设备组。

## 四、验证创建结果

执行：

```bash
id akun
getent passwd akun
ls -ldn /home/akun
```

预期类似：

```text
uid=1001(akun) gid=1001(akun) groups=1001(akun),20(dialout),27(sudo)
akun:x:1001:1001:akun:/home/akun:/bin/bash
```

测试切换用户：

```bash
sudo -iu akun
```

进入后执行：

```bash
whoami
id
pwd
```

应分别看到：

```text

/home/akun
```

然后退出：


## 五、创建用户后的恢复顺序

建议按以下顺序继续：

1. 保留临时管理员 `migration_admin`。
2. 安装新机系统更新、JetPack/CUDA、ROS及基础驱动。
3. 创建并验证 `akun` 用户。
4. 插入备份U盘并确认所有校验和。
5. 先恢复项目代码、配置文件和脚本。
6. 再恢复 ROS bag、地图、模型及车辆运行数据。
7. 恢复 `/home/akun` 中需要的用户配置。
8. 恢复 udev 和 NetworkManager 系统配置。
9. 修复权限并重启。
10. 使用 `akun` 登录，先做静态检查，再连接车辆硬件测试。


## 11. 设置车辆有线网络

- CAN盒：`192.168.1.10`
- 单线雷达：`192.168.1.12`、`192.168.1.13`

```bash
  ipv4.method manual \
  ipv4.addresses 192.168.1.140/24 \
  ipv4.never-default yes \
  ipv6.method disabled
```

启动：

```bash
sudo nmcli connection up car-lan
```

验证：


如果真实网卡名不是 `enp2s0`，必须替换成实际名称。

## 12. 代码恢复后重新安装项目依赖

恢复代码并确认路径为：

```text
/home/akun/workspace/Car_jetson
```

不要直接使用旧机复制来的 `build/`、`install/` 和 `log/` 作为正式运行结果，因为它们可能包含旧机绝对路径和硬件环境。

先加载 ROS：

```bash
source /opt/ros/humble/setup.bash
cd /home/akun/workspace/Car_jetson
```

安装源码声明的系统依赖：

```bash
rosdep install \
  --from-paths real_ws/src \
  --ignore-src \
  --rosdistro humble \
  -r -y
```

旧编译目录不要删除，可以改名保留：

```bash
cd /home/akun/workspace/Car_jetson/real_ws
mv build build.from_old_machine
mv install install.from_old_machine
mv log log.from_old_machine
```

如果某个目录不存在，就跳过对应命令。

按项目真实包名先编译基础驱动：

```bash
source /opt/ros/humble/setup.bash

colcon build \
  --symlink-install \
  --packages-select serial livox_ros_driver2
```

再编译其余驱动：

```bash
source install/setup.bash
colcon build --symlink-install
```

项目说明中写的是 `livox_ros2_driver`，但实际 `package.xml` 中的包名是 `livox_ros_driver2`，新机应使用后者。

# 路线二：如果新机本身是Jetson Orin Nano Super

这种情况下才安装 JetPack。

应使用 NVIDIA SDK Manager 刷入与项目基线一致的：

```text
JetPack 6 系列
L4T R36.4.3
CUDA 12.6
Ubuntu 22.04
```

不要在 Jetson 上先安装普通 Ubuntu，再用通用 CUDA 包拼装环境。JetPack 刷机会清空 Jetson 存储，必须选对目标板和存储设备。

刷机完成后验证：

```bash
uname -m
cat /etc/nv_tegra_release
uname -r

dpkg-query -W \
  nvidia-l4t-core \
  nvidia-jetpack \
  tensorrt 2>/dev/null

/usr/local/cuda/bin/nvcc --version
```

预期重点是：

```text
aarch64
R36.4.3
CUDA 12.6
```

PyTorch应安装 NVIDIA 为相应 JetPack 提供的 Jetson 版本，不要执行：

```bash
pip install torch
```

这可能覆盖 NVIDIA 的 CUDA 适配版本。原基线记录的是 NVIDIA Jetson 版 PyTorch，TensorRT engine 也应在相同 JetPack/TensorRT 环境重新导出或验证，不能只复制后默认可用。

就“迁移当前小车主机”而言，应先完整执行路线一；JetPack/CUDA部分可以跳过。
