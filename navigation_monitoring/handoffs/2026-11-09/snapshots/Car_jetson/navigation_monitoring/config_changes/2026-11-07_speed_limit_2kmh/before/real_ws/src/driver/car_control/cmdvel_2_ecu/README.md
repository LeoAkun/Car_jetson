# cmdvel_2_ecu 速度单位

`/cmd_vel`（或配置的输入话题）使用ROS SI单位：`linear.x` 为m/s，`angular.z` 为rad/s。转换器仅在写入 `Ecu.motor` 时把线速度乘3.6，`Ecu.motor` 继续使用km/h；JD01的CAN编码随后乘10，分辨率为0.1km/h。不要给已经是km/h的 `/ecu` 或底盘速度反馈再次乘3.6。

2026-11-06修复了普通导航将m/s数字直接按km/h下发的问题。实车Nav2配置同步迁移，最高目标保持约3km/h；转换器最终限幅覆盖导航、恢复和网页遥控等输入。充电对接继续使用独立的0.10m/s上限及原有换算，不重复乘3.6。

| 参数 | 当前单位和值 | 迁移前对应的物理值 |
|---|---|---|
| `navigation_max_speed` | 0.8333333333333334 m/s | 约3.0km/h的实车最高范围 |
| `LOW_SPEED_THRESH`（生产配置） | 0.2222222222222222 m/s | 0.8km/h低速补偿 |
| `STOP_THRESH`（普通配置） | 0.005555555555555556 m/s | 0.02km/h停车死区 |
| `Vel_Offeset` | 0.008333333333333333 m/s | 0.03km/h前进偏置 |
| `docking_max_speed` | 0.10 m/s | 对接限速保持不变 |

两份配置文件和源码默认值均使用SI语义。未加载YAML时，源码的低速补偿默认值保留原0.3km/h，换算为0.08333333333333333m/s；生产配置继续使用0.8km/h。`docking_config.yaml` 的普通模式停车死区保留其原0.01km/h物理值，转换为0.002777777777777778m/s；实际对接模式仍使用独立的 `docking_stop_threshold=0.001m/s`。

普通模式先对原始请求判停车，再应用前进偏置和低速补偿，最后限幅。零速及正负停车边界不会被补偿变成行驶命令，档位由最终有效速度决定。转角计算使用未加电机偏置的有符号SI速度。

例如普通请求±0.25m/s，对应ECU目标约+0.93km/h或倒车0.90km/h；正向多出的0.03km/h为保留的校准偏置。补偿后的目标也不超过3km/h。对接请求−0.03m/s仍对应倒车0.108km/h。

低速补偿仍会把停车死区之外、低于0.222222m/s的普通模式请求提升至原0.8km/h目标，因此不能承诺该区间逐点跟随请求。CAN量化、真实底盘响应、里程计坐标系和转向几何还需独立实车验证；此修复不等于完成全部导航验收。

实车Nav2的MPPI线速度上下限、线速度采样标准差及velocity_smoother平移速度/加减速同步除以3.6；角速度、距离、时间和仿真参数不变。配置中的MPPI `ax_max/ax_min` 也迁移为SI值，但当前本地Humble优化器不读取这两个参数，实际平移指令加减速由velocity_smoother约束。

离线回归测试为 `test/test_docking_conversion.py`，使用假时钟和普通Python对象调用转换方法，不初始化rclpy、不创建节点、发布器或看门狗。安装更新只需重建该包；Nav2当前安装配置链接到源码。旧自定义参数文件需一并迁移，不能继续把0.8作为m/s填入低速补偿参数。
