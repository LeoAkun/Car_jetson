# 三轮首次 `lethal-start` 空间对齐分析

分析对象为 2026-11-11 的 15:56、16:30、16:45 三轮录包。全程只读 SQLite 录包和本机文件，没有启动 ROS、传感器、底盘、导航或回放。

## 结论

三轮首次失败都不是“车体中心落在静态地图墙体中”，也没有发现规划器使用了明显错误的全局位置：

- 三轮 Smac 离散起点的静态地图中心格均为自由；含 padding 的矩形 footprint 边界所经过的 30 个 0.10 m 静态格也全部为自由。
- 三轮实际 TF 位姿到失败前最后一条成功全局路径的横向距离分别为 0.085 m、0.054 m、0.070 m。因此现有证据不支持“110 航点较远导致起点坐标错误”或“规划起点已经偏离路径很多”。
- 16:45 可以从录包直接复算：global costmap 的 footprint 边界命中一个 `100` 致命格，静态地图同一格为自由。该格来自 global obstacle layer，而不是 static layer。
- 16:30 的 global/local 都在车体左后方形成近距离动态障碍场；失败时刻的 1 Hz global 完整快照没有留下边界 `100`，但原始合并雷达在 3.5 ms 前有大量小于 1 m 的回波，其中回波只比 padded footprint 左边缘远 11 mm。日志中的 5 Hz 内存态很可能命中了这个瞬时边缘格。
- 15:56 的 global 快照主要显示车右侧静态墙的膨胀带，快照本身不能复现碰撞；但失败前 9.6 ms 的合并雷达有一个点落在配置 footprint 内部，距雷达原点 0.351 m。该点没有被 1 Hz 快照保留，符合“近车体回波在 global 内存态短暂形成 lethal，随后被清除”的时序。

因此，三轮共同问题集中在**近车体合并雷达回波、0.10 m global 栅格离散、footprint 边界清除**的组合；静态地图只在 15:56 提供了一个很近的右侧墙体背景，没有直接与 footprint 重叠。

## 统一几何与判定方式

- 配置 footprint：车体前后 `±0.43 m`、左右 `±0.28 m`；`footprint_padding=0.02 m` 后，Smac 实际使用 `0.90 × 0.60 m` 矩形，即前后 `±0.45 m`、左右 `±0.30 m`。
- 外接半径为 0.541 m，当前 global/local inflation radius 为 0.55 m。这个数值刚好满足 Smac 多边形优化检查要求，不是此次 lethal 的直接来源。
- 静态图与 global costmap 都是 0.10 m 分辨率；配置里的 global `resolution: 0.05` 被 static layer 的地图尺寸覆盖。local costmap 才是 0.05 m。
- Smac 把起点平移到 0.10 m 栅格中心，并把朝向量化为 64 档（每档 5.625°），再沿 padded footprint 边界逐格检查。发布值 `99` 是 inscribed inflation，`100` 才是 lethal；本报告没有把 `99` 当作致命格。

### 15:56

失败前后的三张 global 完整快照都保持中心 36、footprint 边界最高 99，没有录到边界 100，所以不能用这些 1 Hz 快照声称已经精确重放了日志中的判定。右侧最近 lethal 位于 `(157.95,-195.65)`，静态图也是占据格；它的膨胀带把 footprint 右边缘推到 99，但记录快照尚未直接相交。

失败前 9.6 ms 的 `/laser/scan_merge_laser` 有 320 个有限回波，2 个小于 1 m。其中索引 611 的回波为：

- 距离 0.351 m，角度 2.176 rad；
- base_link 坐标约 `(-0.200,+0.289) m`；
- padded footprint 范围是 `x∈[-0.45,0.45]、y∈[-0.30,0.30]`，所以这个点落在配置车体范围内。

global 主快照比该激光帧早约 0.129 s，下一张又晚约 0.87 s，足以漏掉一个 5 Hz 内存态瞬时标记。障碍层按设计会清除 footprint 内部，所以这个点本身还不是致命格的直接证明；它证明了失败时确有近车体观测，是否因 0.10 m 栅格边界离散而未被清除，需要 raw/增量 costmap 才能确定。右侧静态墙让可用余量更小，但静态图没有直接穿入 footprint。

### 16:30

这一轮是近车体动态障碍最密集的一轮。失败前 3.5 ms 的合并扫描有 406 个有限回波，71 个小于 1 m。两个与 footprint 特别接近的点为：

- `(-0.353,+0.311) m`，只比 padded 左边缘多 0.011 m；
- `(-0.366,+0.317) m`，只比 padded 左边缘多 0.017 m。

另有一组约 0.63–0.67 m 的正后方回波，与 global 中车后 lethal 簇一致。local costmap 同时在车体左后方 0.430 m 处保留 lethal，因此这一轮不是 static layer 造成，也不是只有 global 的孤立旧格。1 Hz global 快照没有精确覆盖 planner 报错的 5 Hz 内存态，故不能唯一指定当时命中的某一个栅格；但动态近障碍证据明确。

### 16:45

这一轮证据最完整。事件前约 1.0 s、事件后 1.7 ms、事件后约 1.0 s 的三张 global 快照都能在 footprint 左后边界复算出碰撞。事件后 1.7 ms 的主快照中：

- 起点中心格显示代价 36；
- footprint 边界有一个 `100`；
- 该格中心约为 `(156.15,-192.45)`；
- 相对车体为后 0.369 m、左 0.338 m；
- 静态地图同格为自由。

失败前 6.7 ms 的合并扫描只有一个小于 1 m 的点：距离 0.370 m、角度 2.167 rad，base_link 坐标 `(-0.208,+0.306) m`。它只在 padded footprint 左边缘外 5.8 mm。前面约 0.68 s 内也反复出现同一角度和距离附近的点，能解释 global 中持续的单格 lethal。

local 同时刻在 footprint 周围全为 0。两张地图出现差异并不矛盾：global 为 0.10 m、5 Hz 更新/1 Hz 发布、2.5 m 标记和 3 m 清除、`inf_is_valid=false`；local 为 0.05 m、20 Hz 更新/发布、7 m 标记和 8 m 清除、`inf_is_valid=true`。同一个仅比 footprint 多几毫米的点，在粗栅格 global 上更容易落到边界格，并且 global/local 的清除时序不同。

## 对“膨胀半径与 footprint”的判断

0.55 m 膨胀半径与 0.541 m 外接半径匹配。减小到低于外接半径会破坏 Smac 的优化碰撞检查前提，可能把真实边缘碰撞漏掉，因此不应把降低膨胀半径作为这次问题的主要修复。

更需要处理的是 footprint 与近车体扫描的毫米级关系：

1. 先实测整车、前后雷达外壳和任何突出件相对 base_link 的边界，确认 `±0.45/±0.30 m` 是否覆盖真实车体。当前配置注释也标明这是暂定值。
2. 将两个原始雷达分别投到 base_link 后核对这些 0.35–0.47 m 回波来自真实路沿/障碍、车体自反77是合并器角度/索引造成的重影。若属于车体自身，只过滤真实车体轮廓内部，不应简单扩大近距离盲区。
3. 统一 global/local 的近障碍清除语义，重点检查 0.10 m global 栅格上的 footprint 边界格清除；16:45 已证明 global 留格而 local 清空。
4. 后续录包增加 `/global_costmap/costmap_raw`、global costmap updates、global/local published footprint。当前 `/global_costmap/costmap` 只有 1 Hz，15:56 和 16:30 的 5 Hz 内存态无法逐格还原。

另有一个会干扰判断的日志插桩问题：`obstacle_layer.cpp` 声明了 `total_points`，但遍历点云时没有递增，因此日志持续打印“缓冲区内有效点数为 0”并不代表雷达真的没有有效点。本次原始 scan 已直接证明三轮都有有效回波。
