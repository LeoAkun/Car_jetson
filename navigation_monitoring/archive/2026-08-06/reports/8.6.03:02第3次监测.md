## 原因判断

1. **CPU 过热或主板热保护：高概率。** 启动 `nav2_init_pose` 后温度迅速到 90°C，LIO-SAM 与 Nav2 同时运行后达到 96°C；之前启用保护的测试在 92°C 停栈后整机没有重启。
2. **电源或主板在高负载瞬间触发保护：中等概率。** 硬重启不留内核退出记录，也符合电源瞬态/主板保护表现，需要硬件侧日志或替换电源验证。
3. **Nav2 普通进程崩溃：低概率。** Nav2 逻辑崩溃不会使 boot ID 改变，且关机前 Nav2、管理器、IMU、激光与里程计均在运行。
4. **IMU 数据中断或内存不足：当前证据不支持。** IMU 约 100 Hz，内存余量约 25 GB。

## 后续建议

- 下一次导航前恢复温度保护，不要继续无保护复现；建议 88-90°C 触发立即停车和关导航子栈。
- 先检查 CPU 风扇、散热器压紧情况、硅脂、风道和机箱积尘。当前 `hwmon` 没有提供风扇转速，需现场目视或进入 BIOS 检查。
- 临时关闭 CPU Turbo 或限制最高频率/功耗，再测试重定位、LIO-SAM、Nav2 分阶段启动。
- 将 LIO-SAM 和 Nav2 错峰启动，并在每阶段等待温度回落，避免启动峰值重叠。
- 使用管理员权限读取上一启动周期的完整 `journalctl -b -1 -k`、`/var/log/kern.log` 和 `/sys/fs/pstore`；当前账户无权限，因此不能排除内核 MCE、watchdog 或 ACPI 热事件。
- 若限制温度后仍发生硬重启，优先检查电源额定功率、供电线束、主板 VRM 和 BIOS 硬件事件记录。
