# 2026-11-18 后续导航失败与靠边问题分析

> 2026-11-18 后续处置更新：按现场判断，雷达回波问题暂时移出本轮根因和修复优先级，怀疑回波来自当时车上另一根线。下文雷达统计作为历史证据保留，后续修复与验证以静态足迹合法性、TransformFusion 跳变、恢复倒车、重定位和控制周期为主。第一组滤波暂不删除，退役观察规则见 `../../FILTER_RETIREMENT_POLICY.md`。

## 结论

本段录包覆盖 11:52:39–12:13:48。期间有三次任务进入 Nav2，三次均以 action 状态 `6 (ABORTED)` 结束；另一次任务在重定位阶段失败，没有进入车辆导航。

车辆周围没有实物障碍，并不等于 Nav2 看到的起点可通行。本段失败由三类问题叠加造成：

1. 前雷达有一组随车固定的近车体回波，没有被现有过滤规则覆盖。它落在车体前缘，能够向动态障碍层写入致命格。
2. 若干时刻，定位后的矩形足迹已经与静态地图占据格重叠。此时即使现场为空，规划器仍会判定 `Starting point in lethal space`。
3. LIO TransformFusion 输出 `/odom` 有明显单帧跳变。Nav2 会从跳变后的当前位置重新规划，因此车辆仍能紧跟“最新路径”，但这条路径相对启动时的原路径已经向一侧迁移，现场表现就是严重靠边。

第三次任务还暴露了恢复行为问题：起点已经位于静态地图致命区时，默认行为树仍发布直线倒车，最终把地图中的车辆位置推入更深的占据区，然后倒车失败并中止。

## 固定近车体回波

对全部 22,014 帧 `/laser/scan_front` 逐帧统计后：

- 15,717 帧命中同一回波，占 71.4%。三次 Nav2 任务内的命中率分别为 80.4%、68.2%、69.2%。
- 原始角度中位数约 `-132.00°`，距离中位数约 `0.388 m`。
- 转到车体坐标后，中位位置约 `x=0.450 m, y=-0.107 m`；95% 范围约为 `x=0.447～0.453 m, y=-0.123～-0.076 m`。
- 它跨越不同物理路段仍保持相同车体坐标，因此基本可以确认是自车回波。
- 原始合并 scan 和 filtered scan 的命中率分别为 70.46% 和 70.45%，说明该点没有被过滤。
- 现有规则只过滤前雷达 `+132°～+135°、0.60～0.83 m` 的另一块区域。本录包中该旧规则命中 0 帧。

该点位于当前带 padding 的车体前缘 `x≈0.45 m`，经过 0.10 m 栅格化后可以落到足迹外侧并成为致命格。它能够解释静态地图完全空闲处仍出现的瞬时致命起点，但不能解释所有失败；静态地图足迹重叠必须单独处理。

建议新增第二组严格条件，仅作用于独立 filtered 输出：前雷达原始角度约 `-132.75°～-131.50°`、距离约 `0.33～0.42 m`、转换坐标 `x=0.44～0.46 m, y=-0.14～-0.05 m`。先继续只给全局代价地图使用，局部代价地图和现场保护保持现状，复测后再决定是否扩展。实现时应保留来源、角度、距离、转换坐标四重条件。这个第一阶段可以消除全局规划器受该点影响的致命起点，但局部代价地图仍使用原始 scan，MPPI 受该点影响的问题可能继续存在；若复测确认如此，再增加一条只供局部代价地图使用的窄过滤输出，现场碰撞保护仍保留原始 scan。

## 静态地图与重定位

当前车体足迹加 padding 后约为前后 `±0.45 m`、左右 `±0.30 m`。对 `map2_clean.pgm` 直接采样得到：

- 第一轮末段致命错误位置，车体中心距静态占据格约 0.412 m，足迹已经覆盖占据格。
- 第二轮首次致命错误位置，中心距占据格约 0.316 m，足迹已经覆盖占据格。
- 第三轮 Nav2 刚启动时中心距占据格约 0.412 m，足迹已经覆盖占据格；倒车后中心本身进入占据格。
- 第一轮首次致命错误位置距静态障碍约 3.162 m，足迹完全空闲，因此该次属于动态/瞬时障碍层，不是静态地图。

当前启动门禁只证明定位结果、TF 和 Nav2 生命周期就绪，没有在发目标前验证组合后的 `map -> base_link` 矩形足迹是否落在静态地图自由区。应在启动 Nav2 前增加“足迹合法性门禁”：用最终 `map -> base_link` 位姿栅格化完整足迹及安全边距；若触碰 occupied/unknown，拒绝启动并重新定位，不能只依据 fitness 分数接受结果。

## 严重靠边与位置跳变

相对每轮最新的重规划路径，第一、第二轮横向误差中位数分别只有 0.047 m 和 0.052 m；但相对刚启动时的第一条全局路径：

- 第一轮中位误差 1.434 m，95 分位 3.852 m，最大 3.967 m。
- 第二轮中位误差 0.536 m，95 分位 2.720 m，最大 3.397 m。

这说明控制器多数时间仍在跟随 Nav2 当前给出的路径，真正迁移的是重规划使用的当前位置和随后生成的路径走廊。

100 Hz 里程计进一步给出证据：

- 第一轮 `/odom` 有 18 次单帧位移大于 0.10 m，最大 0.190 m/10 ms；`/odom_incremental` 只有 1 次大于 0.10 m。
- 第二轮 `/odom` 有 33 次单帧位移大于 0.10 m，最大 0.237 m/10 ms；`/odom_incremental` 没有大于 0.10 m 的跳变。
- 第一轮最大跳变集中在任务开始后约 33–35 秒，和相对首条路径最大偏离出现的 30–36 秒区间一致。

代码中的 TransformFusion 在每次收到 LIO mapping odometry 后直接替换 `lidarOdomAffine`，随后将它与 IMU 增量相乘并立即发布 `/odom`，没有对后端修正做连续性限制或渐进融合。这与录包中的输入平滑、输出跳变相符。

车辆转向反馈不支持固定方向的转向零偏：第一轮转向中位数约 `-0.20°`，第二轮约 `+0.16°`，没有两轮一致的持续偏置。该证据不能完全排除轮胎/执行器几何标定误差，但本段首要问题是定位/融合坐标与路径走廊迁移。

## 处理顺序

1. 在发目标前增加静态地图足迹合法性门禁；起点非法时重新定位，禁止进入规划与倒车恢复。
2. 给 filtered scan 增加上述第二组近车体回波掩码，并保持原始 scan 供局部保护使用。复测若只剩 MPPI 局部碰撞，再增加单独的 local-filtered scan，碰撞保护继续使用原始 scan。
3. 对 TransformFusion 增加修正量监测、异常门限和连续化处理。先记录每次 mapping anchor 更新前后的平移/航向修正；超过物理可达范围时拒绝或在 0.5–1.0 秒内平滑应用，同时发布诊断事件。
4. 为 `Starting point in lethal space` 使用专用恢复逻辑：清一次瞬时层并复核足迹；仍非法则停止本轮并重定位，不执行默认 backup。
5. 修复障碍层诊断插桩。当前 `total_points` 初始化后从未递增，所以日志中的“有效点数为 0”是固定误报，不能用于判断雷达掉线。
6. MPPI 计算还有明显超期：第一、第二轮分别有 21 次、40 次 30 Hz 控制周期未达标。将 `controller_frequency` 与 `model_dt=0.05 s` 对齐到 20 Hz，或降低 MPPI 负载后再做单独性能复测；这会加重停顿，但不是本段致命起点的根因。
