# 最后一次 110 -> 114 导航失败分析

## 任务与时间线

- 任务：`task_1794559304`
- 路线：110（5教门口）-> 114（四教返航点十字路口）
- 任务接收：2026-11-13 16:41:44.913 +08:00
- `map -> odom` 就绪：16:47:13.328，平移 `(107.07, -22.21)`
- Nav2 接受首目标110 `(150.90, -110.30)`：16:47:33.835
- 底盘首次反馈非零速度：16:47:36.153
- 首次可见的全局重规划失败：16:47:42.277
- 首次报告 `Starting point in lethal space`：16:49:13.935
- Nav2 状态码6并中止：16:49:20.609

## 已确认的直接失败原因

Nav2 已经正常启动并接受目标，失败发生在行驶后的全局重规划与恢复阶段：

1. `SmacPlannerHybrid` 共27次报告 `exceeded maximum iterations`，无法继续生成到110的有效路径。
2. 行为树共5次调用 `global_costmap/clear_entirely_global_costmap` 超时，清图恢复没有正常完成。
3. 末段两次明确报告 `Starting point in lethal space! Cannot create feasible plan`，说明当时规划起点的车辆足迹已与致命代价区冲突。
4. 恢复次数耗尽后，`bt_navigator` 报告 `Goal failed`，管理器收到状态码6并中止路线；114尚未开始。

因此，最后一次失败不是任务未收到、GPS缺失、LIO-SAM/Nav2未启动或底盘一直驻车。车辆在目标接受后有多段非零速度，状态反馈最高约2.0 km/h。

## 运行特征与配置因素

- 目标接受约2.3秒后车辆开始运动，约8.4秒后出现第一条重规划失败。结合时序判断，初始路径/执行链曾经建立，随后重规划持续失败。
- 任务期间记录到14次规划循环低于目标1 Hz、11次控制循环低于目标30 Hz。大量Hybrid-A*搜索是主要负载来源，也会降低重规划和控制的及时性。
- 当前规划器使用完整分辨率、64个角度格、1.0 m最小转弯半径和最多1,000,000次迭代。车辆一旦靠近代价边界，重新连接到远端目标的搜索空间很大。
- `bt_navigator.default_server_timeout` 当前为30毫秒。对整张全局代价地图执行清除时，这个超时值过短，与本轮5次清图超时直接对应，使恢复链进一步失效。
- 离线检查显示目标110和114均位于静态地图空闲主区域，静态地图本身不存在110与114断开的情况。问题发生在运行时起点/代价地图和重规划过程。

## 已排除的误判

Nav2日志中的“缓冲区内有效点数为0，雷达数据丢失”是现有调试代码误报。`obstacle_layer.cpp` 中 `total_points` 初始化为0后没有递增，因此该告警会反复出现，不能据此认定雷达断流，也不能把它列为本次失败原因。

RViz因X11授权失败退出，但Nav2关键节点随后全部就绪并接受目标；RViz退出与本次导航失败无关。日志中也没有Fast DDS锁或DDS初始化失败证据。

## 当前证据边界

下午这轮没有对应的持续rosbag；现有录包在11:12已经结束。因而无法恢复16:49:13时的全局代价地图、`map -> base_link`精确足迹和原始激光帧，不能仅凭日志唯一确定致命代价来自静态边界、实时障碍还是定位偏移。

此前2026-11-11三轮有完整录包的同类 `lethal-start` 已确认：静态地图足迹为空闲，但近车体合并激光回波会在0.10 m全局代价地图的足迹边缘留下瞬时致命格；其中一轮可直接复算出global costmap边界命中代价100，而local costmap同时为空。最后一轮的“静态区域连通、运行后起点变为lethal”症状与该已知问题一致，所以**近车体回波/global obstacle layer边界留格是当前最高概率来源**，但由于本轮没有同期costmap和scan，仍不能写成已唯一复现。

重定位日志中的 `(109.99, -20.55)` 是搜索输入位置，不是最终车辆的 `map -> base_link` 位姿；不能直接用该点判定车辆压在静态障碍上。管理器实际看到的是 `map -> odom` 平移 `(107.07, -22.21)`。

## 下次测试前的处理顺序

1. 将行为树服务超时从30毫秒提高到能够完成全局清图的量级，并单独验证清图服务时延。
2. 在发任务前保存一帧全局代价地图和 `map -> base_link`，确认完整车辆足迹不在致命/内切代价区。
3. 保留 `/tf`、`/tf_static`、全局/局部costmap、`/plan`、合并激光、里程计和导航action状态的连续录包。
4. 若仍重复达到1,000,000次迭代，再针对该路段验证规划降采样、角度格数量和1.0 m转弯半径；不要只提高最大迭代数，否则会继续拖慢控制循环。
